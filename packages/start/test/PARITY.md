# @effect-trpc/start — tRPC test parity

tRPC has no TanStack Start adapter and no Start tests. The rows below map the tRPC test files
whose _adapter-level_ behaviour this package re-implements for Start; every row is an honest
subset of the tRPC file (the rest of each file is covered by `server`, `client` or
`tanstack-react-query`, or does not apply). Nothing here runs inside a real Start dev server:
the tests drive the handler with fetch `Request`s and the loaders through real
`@tanstack/react-router` objects (`createFileRoute`, `createRootRouteWithContext`,
`createRouter` + memory history).

| tRPC test file                                           | local tests                                             | notes                                                                                                                                                                                                                                                                                                                                                                                                                               |
| -------------------------------------------------------- | ------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| tests/server/adapters/fetch.test.ts                      | `handler.test.ts`, `readme.test.ts`, `start.test-d.tsx` | subset: fetch `Request` → `Response` adapter mounted on an endpoint path (`/api/rpc` + catch-all splat rewriting, custom path, 404 outside it), success / typed failure / defect encoding, streamed responses, non-POST → 405, client end to end through the handler (`httpLink` with a `fetch` into it). Not ported: batching, `createContext`, response meta, URL-encoded GET queries (the effect/rpc HTTP protocol is POST-only) |
| tests/server/createCaller.test.ts                        | `client.test.ts`, `helpers.test.ts`                     | subset: loader-style in-process calls (`createServerClient` / `createIsomorphicClient` with `isServer: true`) return class instances and reject with `TaggedError` instances, with no HTTP (`fetch` spy never called). Context factories and caller-specific errors live in `@effect-trpc/server`                                                                                                                                   |
| client/src/links/localLink.test.ts                       | `client.test.ts`                                        | subset: the isomorphic client picks the in-process link on the server and `httpLink` in the browser; both stream subscriptions and yield instances                                                                                                                                                                                                                                                                                  |
| next/test/issue-4130-ssr-different-transformers.test.tsx | `helpers.test.ts`, `readme.test.ts`                     | the SSR hand-off with a non-JSON data model: Schema-encoded `dehydrate` (ISO dates, plain objects) → JSON → `hydrate` on a fresh `QueryClient` restores `Schema.Class` instances (methods callable), typed errors and infinite pages; also through the TanStack Router `dehydrate` / `hydrate` options after a real `router.load()`                                                                                                 |
| tanstack-react-query/test/queryOptions.test.tsx          | `helpers.test.ts`, `readme.test.ts`                     | subset: `queryOptions` used outside React by a route loader (`ensureQueryData`, `fetchQuery`), proxy memoized per `QueryClient`, `keyPrefix`. React rendering (`useSuspenseQuery`) is covered by `@effect-trpc/tanstack-react-query`; here it is only type-checked (`app.tsx`)                                                                                                                                                      |
| tanstack-react-query/test/infiniteQueryOptions.test.tsx  | `helpers.test.ts`                                       | subset: `ensureInfiniteQueryData` / `fetchInfiniteQuery({ pages: 2 })` from a loader, then dehydrate/hydrate of every page                                                                                                                                                                                                                                                                                                          |
