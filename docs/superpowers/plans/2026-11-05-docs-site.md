# effect-trpc Documentation Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** A VitePress reference site for effect-trpc, styled like effect.website, covering every use
case and advanced usage, with type-checked samples and a JSDoc-generated API reference.

**Architecture:** A private workspace package `site/` holds VitePress config, a custom theme
(CSS variables over the default theme), Markdown pages, type-checked snippet files pulled into pages
with `<<<`, and a generator that turns each package's JSDoc into `site/api/*.md` at build time.
A separate `docs.yml` workflow builds it on PRs and deploys to GitHub Pages from `main`.

**Tech Stack:** VitePress (1.6.x, fallback 2.0 alpha), Vue (VitePress peer), `@fontsource/inter`,
`@fontsource/jetbrains-mono`, optional `@shikijs/vitepress-twoslash`, tsgo, Vitest 5 via
`vite-plus/test`, pnpm 11 workspace.

**Spec:** `docs/superpowers/specs/2026-11-05-docs-site-design.md`

## Review Focus

1. **Base path** — a reader opening `https://rajzik.github.io/effect-rpc-experiment/guide/...`
   gets styled pages and working fonts; every asset URL carries `/effect-rpc-experiment/`. Pinned by
   `site/test/build.test.ts` (Task 1).
2. **Samples drift from the library** — a library change that breaks a sample must fail a PR, not
   ship. Pinned by `docs:snippets` in `docs.yml` (Tasks 4, 13) and the `snippets-used` test (Task 4).
3. **An export missing from the API reference** — namespace members (`Router.make`,
   `Router.isPath`, `Handlers.make`, `Middleware.*`) and sub-entries (`server/node`,
   `electron/main|preload|renderer`) must all appear. Pinned by `gen-api.test.ts` (Task 3).
4. **Dead links between guides and API anchors** — VitePress's dead-link check stays on
   (`ignoreDeadLinks` unset) and API anchors are stable slugs. Pinned by `docs:build` failing on a
   dead link (Task 1, 3).
5. **Dark mode/system theme** — both palettes defined, code blocks readable in both. Pinned by
   `theme.test.ts` checking both `:root` and `.dark` token blocks (Task 2) plus a manual look in
   both themes at 375px and 1280px width.

### Tasks 5–11: Content

Each content task: write the pages and their snippets, run `pnpm -C site docs:snippets`,
`pnpm -C site docs:test`, `pnpm docs:build` (all exit 0), read each page in `docs:dev`, commit
`docs(site): <section>`. Every page follows: one-paragraph purpose → complete sample(s) →
"How it works" → **Gotchas** (from JSDoc Gotchas / README "Known limits") → "See also" links to API
anchors (`/api/<pkg>#<anchor>`). Use VitePress `::: code-group` for multi-file setups and `::: warning`
for gotchas. Facts come from the package READMEs, JSDoc and tests; when a README and the code
disagree, the code wins and the discrepancy is reported to the user.
